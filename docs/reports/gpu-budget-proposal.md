## 3. 阶段计划与假设—假设—实验对应

### Phase 0：不租用（3070，dscs2pc，用户在场时）— ¥0
- **exp001**：延迟基线（PyTorch FP16 / ONNX / trtexec），选定固定学生（≥72 FPS，留 20% 余量）。**所有 H1–H5 的前提。**
- 训练吞吐试跑（exp002 pilot，2k–10k 迭代）：得到 3070 实测 it/s，并用 `scripts/prepare_data.py` 准备评测集（E1/E3，见 datasets.md）。
- **H4 的 TRT FP16/INT8 引擎测量必须在本地 3070 做**（部署目标卡，租用实例的 TRT/卡型不同，数据没有意义）；评测 E1–E4（小数据，LPIPS/tLPIPS）也在本地做，避免把评测集传到租用机。
- 产出：3070 it/s、学生模型、闸门 G0 决策材料。

## 8. 用户要做的 vs agent 要做的

### 用户必须亲自做（agent 不会、也不应该替你做）
1. **AutoDL**：用手机号注册；完成**实名认证**（个人身份证 + 人脸视频，或银行卡 + 预留手机号 + 人脸，或护照等；见 §1）；用微信/支付宝**充值 ¥50**（之后每笔 ≤ ¥100）。
2. **RunPod（仅备选时）**：注册；绑定**信用卡**（官方文档：Visa/Mastercard/AmEx 等经 Stripe；预付卡单笔至少充 $100；也接受加密货币，需先 KYC）。是否接受中国大陆发行的卡【未核实】。新用户可从 $10 起充（官方文档）；**关闭 auto-pay**。
3. 在控制台**创建实例**（4090，PyTorch 镜像，选支持"文件存储"的地区，数据盘保持免费 50GB），并告诉 agent 型号/地区/价格页显示的实时单价。
4. **每次作业结束后核对实例已关机/已释放**，并把账单金额贴给 agent 记账。
5. 批准 G0–G4 每个闸门（逐个回复"批准/不批准"）。

### Agent 来做（不碰账号、不付款）
1. 准备并提交代码：训练/评测配置、每个 run 的启动脚本（带检查点恢复、结束自动关机、日志）、数据打包脚本与校验和（`scripts/prepare_data.py`、`scripts/fetch_data.py` 已有）。
2. 准备数据包与传输清单（见 datasets.md §6），**不传输任何东西到 dscs2pc 或租用机，除非用户指示**。
3. 更新预算：把实测吞吐代入、重算 §3–§4，在每个闸门前给出新的数字；维护 `gpu-ledger.md`（根据用户给的账单）。
4. 结果分析：按 H1–H5 预先定义的 pass/fail 汇总，写入 `docs/issues/` 与 STATUS.md；不凭记忆填数字。
5. 停止规则的执行检查（超时、超支、发散）。

### 两种协作方式（用户选其一）
- **方式 A（推荐，不共享任何凭据）**：agent 把"一条命令"的启动脚本和说明交给用户，用户自己 SSH/粘贴执行并回传日志；成本略高于自动化（用户时间），安全性最好。
- **方式 B（agent 通过 SSH 操作）**：用户把**一次性实例**的 SSH 主机/端口/密码在会话内提供给 agent（不要给控制台登录密码或支付信息）；作业结束后用户释放实例，凭据即作废。agent 从箱子能否连通 AutoDL 的 SSH【未核实】，需在 G1 试一次。
